# Reporting a vulnerability

[English](#english) · [한국어](#한국어)

## English

Report suspected vulnerabilities privately through [GitHub's vulnerability reporting page](https://github.com/mksdr/Miroven/security/advisories/new). Do not disclose exploit details in public issues or pull requests before coordination with the maintainer.

Include the affected version or commit, reproduction steps using synthetic data, the expected security boundary, and the observed impact. Never send real journal content, photos, recovery codes, PINs, encryption keys, credentials, or session cookies. If private reporting is unavailable, do not post exploit details publicly; request a private reporting channel from the maintainer.

Reports should identify whether the issue affects the client, Miroven-API, or their interaction. For the design and its limitations, see the [security model](https://github.com/mksdr/Miroven/wiki/Security-Model). There is no guaranteed response time or published security maintenance schedule.

## 한국어

취약점은 [GitHub 비공개 취약점 신고](https://github.com/mksdr/Miroven/security/advisories/new)로 알려 주세요. 관리자와 조율하기 전에 공개 이슈나 PR에 악용 방법을 게시하지 마세요.

영향받는 버전 또는 커밋, 합성 데이터를 사용한 재현 순서, 예상 보안 경계와 실제 영향을 적어 주세요. 실제 기록·사진·복구 코드·PIN·암호화 키·인증정보·세션 쿠키는 보내지 마세요. 비공개 신고 기능을 사용할 수 없다면 악용 세부사항을 공개하지 말고 관리자에게 비공개 연락 경로를 요청하세요.

클라이언트·Miroven-API·상호작용 중 어느 부분의 문제인지 표시해 주세요. 설계와 한계는 [보안 경계](https://github.com/mksdr/Miroven/wiki/Security-Model.ko)를 참고하세요. 응답 기한과 보안 유지보수 일정은 별도로 보장하지 않습니다.
